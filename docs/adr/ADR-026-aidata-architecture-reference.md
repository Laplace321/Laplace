# ADR-026: AI-DATA 架构参考——有向状态图与 Harness Agent

**状态**: 参考资料  
**日期**: 2026-06-12  
**决策者**: 羽殊

## 来源

钉钉文档：https://alidocs.dingtalk.com/i/nodes/a9E05BDRVQRkezKGCyr5wlPGJ63zgkYA

AI-DATA 是供应链数据分析平台，覆盖 Chat2SQL / Chat2Report / Chat2Excel 全链路。本 ADR 记录其中与 Laplace 多轮对话设计最相关的架构模式。

## 1. 有向状态图（Directed State Graph）

### 选型理由

| 模式 | 排除原因 |
|:---|:---|
| 单次调用/线性链 | 无条件分支，无法回退 |
| ReAct 循环 | 不可控，可能无限循环、幻觉选错工具 |
| Plan-and-Execute | 流程已足够确定，不需要动态规划 |
| 多 Agent 协作 | 单域任务，通信成本不划算 |

最终选型：**有向状态图 + 确定性服务驱动**（LangGraph StateGraph）

```
放弃 ReAct 的"完全自主"  → 换取流程的确定性和可审计性
放弃线性链的"极简实现"  → 换取条件分支和错误恢复能力
→ LLM 只负责语义理解，路由和关键决策由工程规则完成
```

### 与 Laplace 的对照

Laplace 已采用类似理念（ADR-003 AI-Native 架构、ADR-024 两阶段路由），但尚未将其扩展到多轮对话的状态管理。

## 2. Harness Agent 模式

核心理念：**LLM 是能力引擎，确定性服务是缰绳**。

```
传统 Agent（LLM 主导）：
  用户 → LLM 自主选择 → LLM 自主执行 → 结果
  问题：LLM 幻觉导致结果不可预期

Harness Agent（确定性驱动）：
  用户 → LLM识别意图 → 工程规则路由 → LLM生成输出 → 确定性校验 → 结果
         (语义理解)     (不可绕过)      (语义理解)    (不可绕过)
```

### 关键约束

- LLM 只输出意图（MINOR/MAJOR），不输出字段名/表名/值
- Prompt 由工程层动态组装，LLM 收到"填好答案"的上下文
- 五层约束：输入完整性 → 路由确定性 → 上下文压缩 → 状态一致性 → 输出校验

### Laplace 已有的 Harness Agent 实践

- Stage 0/Stage 1 路由由工程代码控制，LLM 只做意图识别和参数提取
- 技能执行器（`executor.py`）是确定性代码，LLM 不参与数据库查询
- 效果匹配规则从 Chaldea Dart 源码声明式提取，非 LLM 生成

## 3. MINOR/MAJOR 意图分类

每轮对话首先判断意图类型：

- **MINOR（追问）**：查询对象没变，复用上轮已选表，跳过选表直接重生成
- **MAJOR（新问题）**：切换查询意图，清空上轮上下文，走完整链路

### 踩坑经验

状态管理的难点在于**标记位的可靠重置**：在多轮交互的多个分支中（人工审核拒绝、用户重新指定、意图跳转等），"是否跳过选表"的标记容易残留，导致 MAJOR 场景错误地复用上轮的错误上下文。

**修复核心**：所有可能触发新问题的路径都必须显式清除该标记，不能依赖默认值。

## 4. 准确率设计中的可借鉴模式

### 确定性优先逐级升级

```
候选 = 1            → 代码直接确认（零 LLM 调用）
候选 > 1 且精确命中  → 代码直接确认（零 LLM 调用）
候选 > 1 且有歧义    → LLM 消歧（设超时降级）
LLM 无法消解         → 向用户展示候选列表
```

Laplace 的昵称解析（`resolve_nickname`）和澄清机制（`ClarificationRequest`）已采用类似模式。

### 主数据补全的三层匹配

```
L1：Trie 精确/前缀匹配（<1ms）
L2：Trie 模糊匹配（拼音/编辑距离）
L3：向量搜索 fallback
```

对应 Laplace 的 `lookup_servant` 三阶段匹配：精确 → 模糊 → 昵称。
